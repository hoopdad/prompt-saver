# Prompt Saver System Design

- **Status:** Implementation-ready
- **Date:** 2026-10-01
- **Normative scope:** Version 1 unless explicitly marked deferred

## 1. Product boundary and invariants

Prompt Saver is a local-first Windows desktop application for capturing, finding,
editing, and copying reusable AI prompts. The first keystroke is the primary
performance outcome.

The following rules are invariant:

1. The editor accepts input before SQLite, search, backups, providers, or
   nonessential migrations are ready.
2. Draft persistence and Library persistence are distinct states.
3. A prompt is committed locally before optional provider work begins.
4. Provider failure never changes a successful local save into a failed save.
5. Prompt text is authoritative and is never rewritten by extraction.
6. An existing intent is automatically selected only at a score of 8500 basis
   points or higher.
7. A score below 8500 creates and assigns a provisional intent when local or
   provider analysis produced a valid controlled verb-object intent. The
   assignment is marked for review.
8. Low-information deterministic analysis never creates an intent. It assigns
   the reserved `Unsorted` intent and marks the prompt for review.
9. All user content is under one data root. Secrets are the only physical
   exception and live in Windows Credential Manager.
10. Version 1 ships as separate self-contained WiX MSI packages for x64 and
    ARM64. MSIX is deferred.

## 2. Architecture and dependency direction

Use a modular monolith:

```text
PromptSaver.Desktop (WPF views, view models, composition root)
        |
        v
PromptSaver.Application (use cases, ports, orchestration)
        |
        v
PromptSaver.Domain (entities, value objects, pure policies)

PromptSaver.Infrastructure (SQLite/FTS, providers, files, credentials, logging)
        | implements Application ports and references Domain
        +---------------------------------------------------------^
```

Rules:

- Domain has no WPF, SQLite, HTTP, logging, or dependency-injection references.
- Application depends only on Domain and defines every external port.
- Infrastructure owns provider wire formats and SQLite rows.
- Desktop contains the only composition root.
- Providers return proposals; they never select intent IDs or write storage.
- The SQLite repository transaction is the sole owner of relational and FTS
  consistency.

## 3. Data root and bootstrap files

One `IDataRootResolver` always resolves:

```text
%LOCALAPPDATA%\PromptSaver\
  prompts.db
  capture-draft.json
  config.json
  Backups\
  Logs\
```

The MSI install directory contains binaries only. Upgrade and uninstall never
delete the data root. A separate, explicit in-app **Delete all local data**
operation may be added after version 1; uninstall does not offer it.

`capture-draft.json` is a small atomic-write file that can be read before
SQLite opens. It contains:

```text
schemaVersion
body
caretOffset
selectionLength
updatedAtUtc
```

It contains no provider data or credentials. Write to a temporary file, flush,
and atomically replace the prior file. Drafts are not searchable, are not
enriched, and have no intent. The file is deleted only after a prompt commit
succeeds or the user explicitly discards the draft.

`config.json` contains only pre-database bootstrap preferences: window bounds,
theme, launch destination, spell-check preference, and unclean-shutdown marker.
API keys are stored in Windows Credential Manager under an opaque target name.

MSIX is not a version 1 channel. If introduced later, it must use the same
unvirtualized data root through `IDataRootResolver` and pass a packaged versus
unpackaged path-equivalence integration test before release.

## 4. Domain model

IDs are UUID v7 values generated by `IIdGenerator`.

### Prompt

| Field | Type | Rule |
| --- | --- | --- |
| `Id` | `PromptId` | Stable identity |
| `Body` | string | Required; exact text; maximum 256 KiB UTF-8 |
| `Title` | string? | User title takes precedence; maximum 200 characters |
| `TitleSource` | enum | `Derived`, `Provider`, `User` |
| `CreatedAtUtc` | instant | Set once |
| `UpdatedAtUtc` | instant | User-visible committed change |
| `LastCopiedAtUtc` | instant? | Copy recency |
| `CopyCount` | long | Incremented after successful clipboard write |
| `IntentId` | `IntentId` | Always assigned on commit |
| `IntentAssignment` | enum | `Unsorted`, `Deterministic`, `AutoMapped`, `Created`, `UserSelected`, `UserCorrected`, `Merged` |
| `IntentReviewState` | enum | `NotRequired`, `NeedsReview`, `Skipped`, `Resolved` |
| `IntentScoreBasisPoints` | int? | `0..10000` |
| `ScoringAlgorithmVersion` | string? | Persisted for every scored decision |
| `MetadataStatus` | enum | `LocalComplete`, `PendingEnrichment`, `EnrichmentFailed`, `ProposalReady` |
| `ContentHash` | bytes | SHA-256 of normalized body |
| `Version` | long | Optimistic concurrency token |

`Unsorted` is a seeded, non-archivable system intent with a stable ID. It is not
an automatic match candidate.

### Intent

| Field | Type | Rule |
| --- | --- | --- |
| `Id` | `IntentId` | UUID v7 except reserved system IDs |
| `CanonicalName` | string | Concise sentence-case verb-object phrase, 3-160 characters |
| `NormalizedKey` | string | Unique NFKC comparison key |
| `Description` | string? | Optional |
| `Source` | enum | `System`, `Deterministic`, `Provider`, `User` |
| `IsArchived` | bool | Excluded from similarity candidates |
| `CreatedAtUtc` / `UpdatedAtUtc` | instant | Audit fields |
| `Version` | long | Concurrency |

Aliases have a globally unique normalized key. If creation resolves to an
archived intent with the same normalized key, unarchive it and record
`IdentityResolutionUnarchived`; do not create a duplicate.

### Persisted intent review candidates

`prompt_intent_candidates` stores the decision-time review set:

```text
PromptId
CandidateIntentId
ScoreBasisPoints
Rank
ScoringAlgorithmVersion
CreatedAtUtc
```

Store at most five candidates scoring at least 6000. Candidate rows are a
snapshot: later renames do not change the recorded score. The UI joins the
current display name and identifies archived or merged candidates.

### Metadata and drafts for existing prompts

- `Skill`, `ProperEntity`, `PromptSkill`, and `PromptEntity` retain source,
  confidence, and extractor version.
- `prompt_edit_drafts` stores one uncommitted revision per existing prompt:
  `PromptId`, `Body`, optional title/metadata edit JSON, `BaseVersion`,
  `CaretOffset`, `SelectionLength`, and `UpdatedAtUtc`.
- Edit drafts are excluded from FTS and enrichment. Committing uses
  `BaseVersion`; a conflict offers reload or save as duplicate.
- Background enrichment never updates a prompt currently open with an edit
  draft. It stores a proposal and sets `MetadataStatus = ProposalReady`.

## 5. Relational schema and ownership

Core tables:

```text
prompts
prompt_edit_drafts
intents
intent_aliases
prompt_intent_candidates
skills
skill_aliases
proper_entities
prompt_skills
prompt_entities
provider_configurations
enrichment_attempts
enrichment_proposals
app_settings
schema_migrations
prompt_search_documents
```

Foreign-key behavior:

- Deleting a prompt cascades to its edit draft, review candidates, metadata
  relations, enrichment rows, and search document.
- Skills and entities orphaned by a prompt deletion are garbage-collected in
  the same transaction unless referenced elsewhere.
- Intents are never automatically deleted. An intent with no prompts or aliases
  becomes archive-eligible.
- Deleting or merging an intent is not implemented as row deletion. Merge
  reassigns prompts and aliases, archives the source, and records the target.

### FTS5: repository-only ownership

There are no FTS maintenance triggers.

`prompt_search_documents` stores normalized NFKC text in `title`, `body`,
`intent_text`, `skill_text`, and `entity_text`. Original text remains in
relational tables.

Create the external-content index with:

```sql
tokenize = "unicode61 remove_diacritics 2 tokenchars '#+.-_'"
```

Every repository operation that changes a contributing value calls exactly one
`ReplaceSearchDocument(promptId)` inside the same transaction:

1. Read the old search-document values.
2. Issue the FTS5 special `delete` command with the old values and rowid.
3. Update or delete `prompt_search_documents`.
4. Insert the replacement FTS row when the prompt still exists.

`RebuildSearchIndex` uses the FTS5 `rebuild` command. Migration, backup, and
repair tests run the FTS5 `integrity-check` command.

The search parser builds a typed AST. Raw user text is never emitted as MATCH
syntax. Literal terms are NFKC-normalized and double-quoted; embedded quotes are
doubled. FTS operators (`*`, `-`, `:`, `(`, `)`, `^`, `NEAR`) are treated as
literal text unless produced by an allowlisted structured parser rule. Prefix
search appends `*` only after quoting a normalized token of at least three
characters. Invalid input returns zero or a validation hint, never a SQLite
syntax exception.

Bare date filters use the user's local timezone. `after:YYYY-MM-DD` means local
midnight inclusive; `before:YYYY-MM-DD` means the next local midnight
exclusive. Bounds are converted to UTC with DST-aware platform time-zone rules.

## 6. Capture, draft, and save flows

### Startup path

Hard path to an editable focused window:

1. Enforce the per-user single-instance mutex.
2. Resolve the data root.
3. Read `config.json` and `capture-draft.json` using bounded small-file reads.
4. Construct and activate the WPF window.
5. Focus the loaded prompt editor and accept input.

After first render:

- open SQLite on a background operation;
- run only compatibility checks needed to determine whether normal use is
  possible;
- initialize search and repositories;
- inspect pending work;
- rotate logs;
- probe loopback Ollama;
- schedule backup or integrity work.

If SQLite is unavailable or migration recovery is required, the editor remains
memory-backed. The UI says text is not yet persisted and offers **Copy text**.
Draft file persistence continues when the data root is writable.

`PRAGMA quick_check` runs after an unclean shutdown and during explicit
maintenance, not on every launch. A pre-migration online backup is taken only
when a migration is pending. Migration work may show a determinate recovery
surface after the editor is already usable.

Targets are measured separately:

| Metric | x64 target | ARM64 target |
| --- | --- | --- |
| Warm activation to editable focused editor | p50 < 400 ms, p95 < 800 ms | p50 < 550 ms, p95 < 1000 ms |
| Database ready, no migration | p95 < 1500 ms | p95 < 2000 ms |
| Local prompt commit | p95 < 75 ms | p95 < 100 ms |
| 50,000-prompt first search page | p95 < 100 ms | p95 < 150 ms |

Release packages use ReadyToRun on both architectures. PR CI reports startup
timings; dedicated native release machines enforce budgets.

### New capture draft

- Debounce draft writes by 400 ms after input and flush on deactivation/close.
- Never move caret, selection, scroll position, undo history, or IME state.
- Draft write failure is persistent and assertive once. The editor stays usable
  and exposes **Copy text** and **Try again**.
- A recovered draft restores caret/selection when valid, otherwise places the
  caret at the end.

### Prompt commit

1. Reject whitespace-only body.
2. Reject content above 256 KiB UTF-8; never truncate automatically.
3. Disable duplicate commit command execution while one is in flight.
4. Run deterministic extraction.
5. Resolve the initial intent using the rules in section 7.
6. In one transaction insert prompt, local metadata, assignment, review
   candidates, and search document.
7. Return `Prompt saved` while keeping text, caret, selection, and undo history.
8. Delete `capture-draft.json`.
9. If an enabled provider is allowed for this prompt, enqueue enrichment.

`Ctrl+Shift+C` copies current editor text only. It never saves. A separate
**Save and copy** command may use `Ctrl+Shift+Enter`.

## 7. Deterministic intent and the 85% rule

The deterministic extractor uses a versioned controlled action vocabulary:

```text
create, write, draw, summarize, analyze, fix, explain, search, prepare, convert
```

It may create a candidate only when it recognizes:

- a controlled leading action, and
- a non-stopword object noun phrase.

It may append one broad qualifier, such as `for a customer`, only when it
changes the reusable goal. The fallback `save prompt about <keywords>` is
prohibited.

When no valid candidate exists:

- assign `Unsorted`;
- set `IntentAssignment = Unsorted`;
- set `IntentReviewState = NeedsReview`;
- create no new intent.

When a valid candidate exists, score it against active intents and aliases.
Lexical scoring uses the median of:

1. token-set Sorensen-Dice;
2. character trigram cosine;
3. normalized edit similarity.

An automatic mapping also requires at least one shared non-stopword object
token. Exact normalized canonical matches score 10000. Exact alias matches
score 9900.

Version 1 has no embeddings. This keeps the 85% decision deterministic across
provider configurations. Embeddings are deferred and would require a new
algorithm version and explicit re-review, never retroactive reassignment.

Decision rule:

| Best score | Persisted result |
| --- | --- |
| `>= 8500` | Assign existing intent, `AutoMapped`, `NotRequired`; persist top review candidates for audit |
| `< 8500` with valid candidate | Create/identity-resolve provisional intent, assign `Created`, `NeedsReview`; persist up to five existing alternatives scoring `>= 6000` |
| No valid candidate | Assign `Unsorted`, `NeedsReview`; persist any useful existing alternatives |

Exactly 8500 maps. 8499 creates a provisional intent. Review actions are:

- **Keep provisional:** assignment becomes `UserSelected`, state `Resolved`.
- **Choose existing:** assignment becomes `UserCorrected`, state `Resolved`.
- **Rename provisional:** update or identity-resolve, add the prior wording as
  an alias when safe, assignment becomes `UserCorrected`, state `Resolved`.
- **Review later:** keep the current assignment and set state `Skipped`.

No-provider taxonomy bound acceptance test: saving 100 prompts whose text has
no valid controlled verb-object clause creates zero user intents and assigns
all 100 to `Unsorted`.

## 8. Reclassification, merging, duplication, and deletion

### Reclassify a prompt

The user may select an existing intent or create a new one. This updates only
the prompt assignment, clears review, rebuilds the search document, and never
changes prompt text.

### Merge intents

`MergeIntents(source, target)`:

1. Rejects merging `Unsorted` into or from another intent.
2. Reassigns source prompts to target with `IntentAssignment = Merged`.
3. Moves non-conflicting aliases; records conflicts for review.
4. Adds the source canonical name as an alias when available.
5. Archives source and records `MergedIntoIntentId`.
6. Clears or remaps affected candidate rows.
7. Rebuilds all affected search documents in the same transaction.

### Duplicate prompt

Duplicate creates a new prompt ID with the same body, title, accepted metadata,
and current intent. It clears copy history, enrichment attempts, pending
proposals, and review candidates; assignment is `UserSelected` and review is
`Resolved`. It does not copy an edit draft.

### Delete prompt

Delete is permanent in version 1 and requires confirmation. The transaction
issues the FTS `delete`, deletes the prompt, applies cascades, garbage-collects
orphaned skills/entities, and marks newly orphaned intents archive-eligible.
After deletion, the UI focuses the next result or the prior result when the last
item was deleted.

## 9. Provider discovery, privacy, and limits

Providers are optional and disabled until the user enables one.

### Automatic Ollama discovery

After first render, once per app version or after dismissal expiry:

1. Send `GET http://127.0.0.1:11434/api/tags`.
2. Use a 500 ms connection timeout and 1 second total timeout.
3. Send no prompt, intent, identifier, header credential, or telemetry.
4. Do not follow redirects and do not probe `localhost`, LAN, or remote hosts.
5. On success, show a dismissible modeless affordance:
   **Local Ollama detected - enable AI metadata?**
6. Never auto-enable enrichment or select a model without user action.

Settings model discovery uses the configured endpoint and remains cancellable.

### Version 1 providers

- Ollama local HTTP API.
- Azure AI Foundry/OpenAI-compatible endpoint with API-key authentication.

Microsoft Entra authentication, `Azure.Identity`, embeddings, and automatic
historical backfill are deferred.

### Payload and output caps

Provider requests contain:

- at most the first 8192 UTF-8 bytes of prompt body, cut at a valid UTF-8
  boundary and preferably a paragraph boundary;
- a `contentTruncated` boolean;
- no existing intent catalog and no intent IDs;
- schema/version instructions only.

Provider responses are limited to 64 KiB and validated to:

- title <= 200 characters;
- intent <= 160 characters;
- at most 20 skills and 30 entities;
- each value <= 160 characters;
- allowlisted entity types and confidence range.

Remote providers require HTTPS. Plain HTTP is allowed without warning only when
the parsed host is an IP loopback address. Other HTTP endpoints require an
explicit warning acknowledgement.

Settings states exactly what leaves the device: the capped prompt excerpt and
schema instructions. It states that intent matching occurs locally and the
intent catalog is not transmitted. Logs and diagnostics contain no prompt
body, extracted values, credentials, request/response bodies, or raw endpoint
query strings.

Enrichment uses one worker. The current-session queue cap is 20 prompts. Enabling
a remote provider enriches new saves only; backfilling existing prompts is a
future explicit action requiring confirmation and a displayed item count.

## 10. Backups, migrations, and recovery

- Migrations are immutable embedded SQL with IDs and checksums.
- When a migration is pending, create an online SQLite backup before applying
  it.
- Each migration is transactional and followed by foreign-key and FTS
  integrity checks.
- Daily backup runs after first render and only when the database changed since
  the last successful backup.
- Retain seven daily backups. Weekly tiers and diagnostics zip export are
  deferred.
- Restore first preserves the current database as a timestamped recovery copy.
- An unclean shutdown schedules `quick_check`; failure switches SQLite to
  read-only recovery while preserving the emergency editor.

## 12. Test boundaries and required cases

### Domain

- controlled extraction and low-information `Unsorted` behavior;
- NFKC normalization, aliases, object-token guard, and adversarial near misses;
- `8499` creates/review, `8500` maps, `8501` maps;
- deterministic tie breaking and archived-intent exclusion;
- merge invariants and user assignments resisting background overwrite;
- 100 unrelated low-information prompts create zero user intents.

### Application

- draft recovery and draft-write failure;
- commit keeps editor state and deletes the capture draft only after success;
- provider absence/failure cannot fail local save;
- review later retains provisional assignment;
- confirm/reclassify resolves review;
- duplicate, delete, merge, and optimistic-concurrency outcomes;
- open edit surface converts enrichment to a proposal instead of a write;
- payload cap and no intent-catalog transmission.

### Infrastructure

Use temporary on-disk SQLite databases:

- migrations, WAL, busy behavior, backup, restore, and corruption recovery;
- repository-only FTS replacement after body, title, intent, skill, entity,
  merge, and delete changes;
- removed terms return zero results and FTS integrity checks pass;
- tokenizer cases for `C#`, `C++`, dotted names, hyphens, underscores,
  full-width forms, accents, ligatures, quotes, operators, and malformed input;
- local-date filtering across a DST transition;
- cascades and orphan collection;
- provider HTTP limits, timeouts, redirect refusal, schema validation, and
  redaction;
- data-root and credential-store adapters.

### Desktop and release

- view-model command, focus, state, and announcement tests;
- UI Automation checks with FlaUI for capture, search, copy, intent review,
  delete focus recovery, dialogs, provider errors, and recovery;
- manual Narrator, 200% scaling, contrast-theme, IME, and clipboard-contention
  qualification;
- native x64 and native ARM64 startup and package smoke tests.

Package and UIA tests are release/packaging stages, not default inner-loop
tests. Package tests skip with a clear message unless `PROMPTSAVER_ARTIFACTS`
points to published artifacts.

## 13. Version 1 scope and deferred work

Version 1 includes capture/edit drafts, prompt CRUD/duplicate, local metadata,
deterministic intent policy, review/reclassification/merge, SQLite/FTS search,
copy and copy-with-metadata, Ollama plus API-key OpenAI-compatible enrichment,
backup/restore, basic local diagnostics, accessibility, and x64/ARM64 MSI.

Deferred: MSIX, embeddings/vector index, Entra authentication, cloud sync,
telemetry/exporters, diagnostics zip, weekly backup tiers, automatic historical
provider backfill, recycle bin, global hotkey/tray capture, and start-at-login.
